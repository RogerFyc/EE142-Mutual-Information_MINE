# MINE Reproduction

This is a compact PyTorch reproduction of **Mutual Information Neural
Estimation** (arXiv:1801.04062v5). It includes the core estimator, simplified
Section 4.1 / 4.2 experiments, and a runnable 25-Gaussians Information
Bottleneck application experiment. The
`mine-pytorch-master` directory in the workspace was used only as a reference;
this implementation is independent and does not depend on old PyTorch
Lightning APIs.

## Scope

Implemented:

- Donsker-Varadhan MINE objective:
  `I(X;Y) >= E_joint[T_theta(X,Y)] - log E_marginal[exp(T_theta(X,Y))]`
- EMA gradient correction for the denominator in Algorithm 1.
- Joint and product-of-marginals terms use independent sample batches. This is
  important at high MI: an in-batch permutation with fixed points can impose an
  artificial estimate near `log(batch_size)`.
- MINE-f objective:
  `E_joint[T_theta(X,Y)] - E_marginal[exp(T_theta(X,Y) - 1)]`
- Section 4.1 style correlated Gaussian MI estimation.
- Optional KSG/Kraskov nearest-neighbor baseline for Figure 1 style plots.
- Section 4.2 style nonlinear dependence experiment with 2-dimensional random
  variables and `identity`, `cubic`, `sin(x)` transforms.
- MINE-regularized Information Bottleneck toy experiment.

## Gaussian MI Experiments

Paper Figure 1 includes both bivariate Gaussian variables and 20-dimensional
Gaussian variables. In this repo, `--dim 1` corresponds to a bivariate Gaussian
pair `(X,Y)`, and `--dim 20` corresponds to 20 correlated coordinate pairs.

### Match mine-pytorch-master

The saved `mine-pytorch-master/figures/mi_estimation.png` was generated by its
`All Experiments.ipynb` with `dim=1`, 3000 fixed train/test samples, batch size
500, 200 epochs, a 100-100 ReLU statistics network, and the objective called
`mine_biased` in that repository.

Use the matching preset:

```powershell
python .\scripts\run_gaussian_mi.py --preset reference --paper-panel 2d --outdir .\outputs\reference_mine_pytorch
```

The reference repository's saved image contains only the bivariate experiment.
It does not contain a `dim=20` panel. Running `--preset reference --dim 20` is
therefore an extrapolation, not a reproduction of that saved image.

For the complete left panel with MINE, MINE-f, Kraskov, and true MI:

```powershell
python .\scripts\run_gaussian_mi.py --preset reference --paper-panel 2d --rhos -0.99 -0.9 -0.7 -0.5 -0.3 -0.1 0 0.1 0.3 0.5 0.7 0.9 0.99 --loss biased fdiv --epochs 200 --samples 3000 --batch-size 500 --include-kraskov --kraskov-samples 10000 --outdir .\outputs\paper_2d
```

Here `dim=1` is the dimension of each variable. The plotted joint pair
`(X_a, X_b)` is 2-dimensional, so result CSV files also include
`joint_dim=2`.

If `scikit-learn` is not installed, the script prints a skip message instead
of failing the MINE experiment.

The analytic Gaussian MI is:

```text
I(X;Y) = -0.5 * dim * log(1 - rho^2)
```

For `dim=20` and `rho=0.99`, the analytic value is about `39.17`, while the
paper's finite-training MINE curve is around `23`. A 5000-step CPU run usually
underfits this point. With independent marginal samples and 20000 steps, a
diagnostic run with seed 7 reached `23.02`.

## Gradient Clipping

Gradient clipping is disabled by default to better match the Section 4
estimation experiments. If training becomes unstable, enable it explicitly:

```powershell
python .\scripts\run_gaussian_mi.py --clip-grad-norm 5.0
```

## Differences From Full Paper

- The application experiments are runnable 25-Gaussians reproductions. The
  paper's larger image experiments such as Stacked MNIST are not bundled,
  because that would add mandatory dataset downloads and extra dependencies.
- Kraskov-style nonparametric baselines are optional and require scikit-learn.
  Without scikit-learn, Figure 1 style plots compare MINE, optional MINE-f, and
  the analytic Gaussian ground truth.
- Gradient clipping is off by default; adaptive gradient clipping is discussed
  in the paper's later application experiments rather than the basic Section 4
  MI estimation setup.
